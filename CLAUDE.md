## Project overview
**FinanceTracker** is a **personal finance tracker**. Since **v2.0.0 (2026-08-23) the backend is a Cloudflare Worker over Cloudflare D1** — one Worker serves the PWA, the JSON API, the Telegram bot and two cron jobs. Google Sheets is gone as the source of truth (frozen archive; the v1 backend is `git show v1.9.2:Transactions.gs` etc.).
- **Three ways in, one set of handlers:** the **PWA** (`worker/public/`), the **Telegram bot** (`worker/src/telegram.js`), and **Gmail ingest** (Apps Script courier → `?action=ingestEmail`). All route through `worker/src/api.js`.
- **What is left in Apps Script:** `Gmail.gs` (mail courier, 5-min trigger) and `Backup.gs` (nightly dump into a spreadsheet). **No Web App deployment, no `doGet`/`doPost`, no `deploymentId`, no `GAS_URL` secret.** `GmailApp` is the only reason GAS survives at all — free OAuth to the owner's mailbox with no off-platform equivalent.
- **Locale:** amounts in **PHP**; timezone `Asia/Manila`.
- **History:** v1 (GAS + Sheets, v1.0.0→v1.9.2) is the design record — `git show v1.9.2:CLAUDE.md` for the sheet-era lore, `git show v1.3.4:OVERHAUL_PLAN.md` for the original overhaul. The v2 execution plan is **`D1_MIGRATION.md`** — still in the tree because the cutover is owner-side and pending (HANDOFF.md is the runbook); delete it once v2.0.0 is verified live.

## The database (`worker/migrations/0001_init.sql`)
Tables: `account_types · accounts · categories · transactions · budgets · recurring · ledger (+ ledger_view) · prices · nw_snapshots · email_quotes · seen_updates · meta`.
- **Money and quantities are INTEGER MICROS** (`*_u` = native units × 1e6). Exact integer sums, and the same column holds a fractional IBKR share quantity (a Shares row's amount IS a quantity, as in the sheet). **Convert at the API boundary only** (`toU`/`fromU`); a decimal mid-calculation is the drift the integers exist to prevent.
- **Dates are `yyyy-MM-dd` TEXT; month keys are `yyyy-MMM` (`2026-Aug`) everywhere, DB included** — the SPA, the Gemini prompt and Budgets all compare that exact shape.
- **Two generated columns, both STORED:** `transactions.month` = `COALESCE(period, <substr trick on date>)` (the Period override, replacing the ARRAYFORMULA and the `@`-text-format gotcha) and `amount_php_u` = `CAST(ROUND(amount_u * COALESCE(fx_rate,1)) AS INTEGER)`. **`ROUND` before `CAST`** — CAST alone truncates toward zero, which negative amounts expose immediately. **They use `substr`/`CAST` and NOT `strftime`:** SQLite registers the date/time functions as non-deterministic (they can read `'now'`) and a generated column may only call deterministic ones, so `strftime` fails at CREATE TABLE time. `test.js` asserts `monthOf()` and the substr expression agree.
- **`ledger_view`** does what the sheet's per-row formulas did: `LEFT JOIN transactions` on the **soft** `tx_id` (deliberately no FK — a deleted tx must render `⚠ transaction deleted`, not block the delete), deriving Date Received / Reporting Period / Wise Amount / Total Income / 8% Tax. `date_received`/`wise_amount_u` are literal fallbacks for legacy rows that were never linked.
- **`meta`** replaces Script Properties and is editable in the admin grid: `data_version`, `monthly_income_php`, `usd_php_fallback`, `owner_email`, `ledger_first_year`, `tg_last_ids`.
- **`prices`** is `(symbol, priced_at)` — history is free and is the audit trail the Sheet never had. `accounts.symbol` is the IBKR ticker (it used to live only inside the GOOGLEFINANCE formula). **Nothing fetches a price on the read path.**
- **`nw_snapshots`** is `(month PK, net_worth_u, assets_u, liabilities_u, shares_u, taken_at)` — the REAL monthly net worth the on-demand fold can't reconstruct (it always computes at today's FX/prices, and no historical FX is stored). Written by the daily cron (`api.js snapshotNetWorth`, upsert by month, so a month's last write is its close); signs match the API (liabilities positive, netWorth signed, shares⊂assets). `getDashboard` serves it as `netWorthHistory` (live month omitted — the chart uses live `netWorth` there); the SPA falls back to rolling cash flow backward for months with no snapshot yet. **History only accrues going forward** — pre-migration months stay estimates forever.
- **Balances are computed, not stored** (`db.js deltas()` + `shapeAccounts()`): native = `starting_balance_u` + Σ deltas, where **Income adds, Expense and Transfer subtract from the source, a transfer adds `to_amount_u` to the destination, and a LIABILITY account's delta is inverted** (it tracks an amount owed, so a charge raises it). PHP: PHP as-is; other currency × live FX; Shares × `prices` × the quote currency's FX. `availableCredit` = limit − balance for liabilities. The API fields keep their exact v1 names/signs: `balancePhp` (liabilities positive), `balanceNative`, `netWorthPhp` (signed), `availableCredit`, `isLiability`, `isShares`, `isInvestment`.

## How the backend works
**Contract:** the `/api` JSON contract is the v1 contract, deliberately unchanged — same `?action=` names, same argument names in the sheet's header casing (`Category`, `Amount`, `Amount (PHP)`), same `{status:'error'|'duplicate'}`, same `version` protocol. That's why `app.js` needed no changes outside the Admin screen, and `migrate/verify.js` is what proves it.
**Routing:** GET `?action=` → `ROUTES_READ`, POST → `ROUTES_WRITE`. **Read/write is derived from the `get…`/`list…` handler-name prefix**, which is also how the SPA's `gs()` picks its method — one list, not two. `test.js` fails the build if a route is named against the rule (this is why `exportAll` from the plan is `getExportAll` here).
**Writes:** every write handler puts its statements **and `bumpStmt(env)` in one `env.DB.batch()`**. D1 batches are transactional, so this replaces `su_lock_()` + `cache_bumpVersion_()` entirely: no lock to take, no bump to forget, no window where a reader sees the write but the old version. `test.js` asserts every `ROUTES_WRITE` handler mentions `bumpStmt`.
**Idempotency:** `createTransaction`/`createTransfer` are `INSERT … ON CONFLICT(id) DO NOTHING` + `meta.changes===0` → `{status:'duplicate'}`. **The SPA's offline queue and Telegram's retry dedup both depend on that exact contract** — `test.js` guards all three parts of it.
**Auth:** cookie or bearer, both accepted on every action (there is one user). The **app shell is intentionally public** — no data, no secrets in it — which is also what keeps assets free and unmetered; only `/api`, `/login`, `/tg` burn invocations.
**Timezone:** Workers and D1 run in UTC. **Every "today"/quarter goes through `manilaToday()`.** A bare `new Date()` in a date-deciding path is a bug for eight hours out of every twenty-four; `new Date().toISOString()` as a *timestamp* is fine.
**FX:** `fx_rate` is a **static value stamped once at write time** — history never reprices. Reads use `fxRate()`, which is a 6h KV entry, so a page load costs a network hop at most four times a day. `SHARES` short-circuits (it's a quantity, not a currency).
**Cron:** `0 22 * * *` (06:00 Manila), one trigger doing two jobs in order: IBKR prices, then the net-worth snapshot (upserts the current month, so daily runs keep it fresh and the last run of a month is its close). **The free plan does not retry a failed cron**, so `runCron` catches and Telegrams the owner; a missed night is harmless (prices go one day staler; the snapshot fills on the next run).
**IBKR Flex:** `SendRequest` → ReferenceCode → `GetStatement`, polling while `ErrorCode 1019` ("generation in progress"). **A `User-Agent` header is required** or IBKR answers 403. Positions are parsed by regex (Workers has no XML parser) — the moment that needs real XPath, the query is asking for too much. **Quantities are logged, never written:** the ledger stays the source of truth for how many shares are held; IBKR only prices them.

## Web App frontend
**Serving:** the Worker serves `worker/public/` as static assets, same origin as `/api`. No bundler, no build step.
**Data path:** `gs(fn, arg)` → `/api`. Reads GET, writes POST, chosen from the handler-name prefix. `gs()` rejects on `{status:'error'}`, and on a **401** asks for the passphrase once (`unlock()` → `POST /login`) and retries. `unlock()` renders a **real `<form>` in the app's own modal — never `window.prompt`**: prompt shows the passphrase in clear text, no password manager can fill it, and its iOS field autocapitalises. `type=password` + `autocomplete="current-password"` (plus a readonly username field so the saved entry has a name) is what gets iOS AutoFill. Concurrent 401s share one dialog (`_unlocking`); a wrong passphrase re-asks in place; cancelling must settle the promise (`closeModal.onClose`) or every later 401 awaits a dead one.
**Screens:** Dashboard · Transactions (filters/pagination + the Edit toggle: account rail, checkboxes, bulk bar, inline single-field edit — one `txRow(t,opts)` renders both modes; `?screen=review` is dead) · Budgets · Accounts (incl. the Holdings, Quarterly-pulse and Emergency-runway cards, all filled by one `cachedCall('investments')`) · Swap · Tax · **Admin**. Deep links: `?screen=<name>` wins over the stored last screen; `?tx=<ID>` opens that transaction's edit modal (the Telegram receipt's target) via `openTxById`. Mobile-first: bottom-nav + a More sheet on phone, left sidebar ≥860px.
**Admin screen (new in v2.0.0):** a generic CRUD grid over the server-side whitelist. **The Sheet used to be the admin UI** — adding a category, retiring an account, fixing a budget target were all "open the tab and edit the cell" — so this replaces exactly that. It renders whatever `listTable` tells it: the server owns which tables exist, which columns are editable (`edit`), which are settable on insert (`add` — a natural PK appears there and not in `edit`, because renaming one under a live FK is data loss, not a cell edit) and which are micros (`money`, converted both ways at the boundary). **`transactions` is read + delete only** — it has real handlers with validation and FX stamping, and the grid must not be a way around them. **`nw_snapshots` is fully read-only** (`edit:[]` + `nodelete:true`): cron-owned history the grid must not hole; `listTable` reports `deletable:false` and the client hides the ✕. No SQL console, deliberately: anything this can't express is `wrangler d1 execute`.
**Tax screen:** `getLedger` returns `rows` keyed by the **sheet's old header names** (`__row` is now the ledger row id — an opaque handle, so the client is unchanged), `cols` in `LEDGER_COL_ORDER`, and `derived` (rendered read-only). `Filed?` is a native `<select>` of BIR quarters (`quarterSelect`), deliberately not the fuzzy combobox. The subtitle links out to the BSP daily rate page — **`BSP Reference Rate` is deliberately not the app's FX**: BIR wants the central bank's reference rate on the date of receipt, which the app has no feed for, so it stays hand-typed per payslip. The "Salary not in the ledger" card lists `unlinked` and "+ Add" appends a row writing *only* `Transaction ID`; everything else derives.
**Non-obvious UI constraints:** chart series tokens `--chart-income #27ad75` / `--chart-spend #d95757` (red, = `--chart-neg`; was blue `#5b8cff` until spending went red) are contrast-validated against the card surface — revalidate if changed. **Income-green vs spending-red is a red/green CVD-confusable pair**, mitigated by position (income bar left, spend right), the legend, and the tooltip — colour is never the only channel. The net-worth line is `--accent` (blue), distinct from both. Form/filter pickers are a custom **fuzzy combobox** (`comboEl`/`fuzzyScore`), deliberately not `<select>`. The quick-add **FAB adds transfers too** — `typeToggleEl` swaps `openTxModal`⇄`openTransferModal` in place, carrying Date/Account(→From)/Amount/Description but **not** Category (disjoint sets).
**Perf:** payloads are cached client-side (`S.cache`, persisted to localStorage) and revalidated through `cachedCall` + `getDataVersion`. Dashboard/Budgets keys are month-scoped, so `monthPickerEl` must **not** wipe `S.cache` on change. `VER_TTL=3000` kills duplicate version pings from a re-render or a tab flip. Transactions add/delete are optimistic. **`LS_SCHEMA` is a cached-payload shape stamp — bump it whenever a payload's shape changes** (it went to 2 for the D1 cutover). **There is no push:** a screen left open never updates itself; the app revalidates on navigation.
**App-shell scrolling (v1.6.5), don't undo it:** `html,body{overflow:hidden}` and `#app` is exactly one viewport tall, so **`.main` is the only scroller** — the document must never scroll, or iOS rubber-band overscroll drags the topbar/nav off the screen edges. Height comes from **`--app-h`, set in JS in `index.html` before first paint**, because iOS standalone + `black-translucent` + `viewport-fit=cover` reports `innerHeight` as **screen minus the top inset** (797 vs 844 on a 390×844 phone) while painting from y=0 — only `screen.height` sees it, and the shim keys on `screen.height === innerHeight + insetTop` so every other platform falls through. The nav's ~34px bottom padding **is the home-indicator clearance, not a bug**. Changing `apple-mobile-web-app-status-bar-style` is not a fix path: **iOS reads those metas at Add-to-Home-Screen time.**
**Offline (v1.6.1):** three layers. **Shell** — `sw.js` caches `/`, `/app.css`, `/app.js`, `/manifest.json` cache-first (`ignoreSearch`, so a deep link matches the cached `/`); it deliberately **never caches `/api`**. **Reads** — the persisted `S.cache` (a failed revalidation keeps the stale paint). **Writes** — a `localStorage` queue (`ft.queue`) flushed on `online`, at launch, and by Refresh. **Only `createTransaction`/`createTransfer` are queued** (`QUEUEABLE`) because only they are idempotent on a client-supplied ID — `gs()` stamps a `ui-<ts>-<rand>` ID *before* the first attempt for exactly that reason. Everything else refuses with an offline message. Pending rows are derived from the queue (`rebuildPending`). A flush **discards a queued write only when the server explicitly rejects the payload** (`_server`); offline, a lapsed cookie, a cancelled prompt or a 5xx all keep it and stop the run — dropping money because the cookie lapsed would be the worst bug in here. `flushQueue._busy` is what stops `gs()` re-queueing during a flush.

## Git workflow (gitflow + releases)
- **`main`** = released/live code only. **`develop`** = integration branch; day-to-day commits and merges land here.
- **Features:** `feature/<name>` off `develop`, merge back to `develop`.
- **Release:** merge `develop` → `main`, then `npm run release` — the ONLY way code reaches live. It verifies on-main+clean, applies D1 migrations, `wrangler deploy`s, tags `v<package.json version>`, pushes, creates the GitHub Release. Bump the version **before** merging (`npm version patch|minor --no-git-tag-version` on `develop`, commit).
- **Hotfix:** `hotfix/<name>` off `main` → merge to `main`, bump patch, `npm run release`, then **back-merge `main` → `develop`**.
- **Tags/Releases invariant:** every tag is `vX.Y.Z`, on `main`, created only by `release.js`, with a matching GitHub Release. Never hand-create tags or Releases.
- Push `develop` freely; never push directly to `main`.

## Conventions & gotchas
- **Never commit credentials** or any URL/id that acts as one. `.clasp.json` (`scriptId` only) is safe; `worker/.dev.vars` and `.clasprc.json` are gitignored.
- **A new UI-callable handler must be registered in `worker.js`** — `ROUTES_READ` (named `get…`/`list…`, GET) or `ROUTES_WRITE` (POST). Unregistered = "Unknown action".
- **Every new write handler ends its batch with `bumpStmt(env)`** — in the SAME `batch()` as its writes. `test.js` enforces it.
- **Convert micros at the boundary, never mid-logic.** `ROUND` before `CAST` in any SQL that produces an integer amount.
- **Every "today" goes through `manilaToday()`.** A defaulted transaction date and the BIR quarter window are the two places a UTC slip silently corrupts data.
- **Month keys are `yyyy-MMM` with exactly that capitalisation, everywhere.**
- **The Growth segment rides the FUNDING transfer** (Wise→IBKR, category `Investment: Growth`, budget Monthly $200 = "did I park this month's $200"); broker buy legs (IBKR→ticker/IB01) and EF parking are `Transfer: Internal` — tagging both legs double-counts budget actuals. **There is deliberately NO Stability category or budget row** (removed 2026-08-26): EF accrues as unspent residue, which a monthly meter can't track — the Emergency-runway card is the only EF measure. The convention lives in the category DESCRIPTIONS (which the Gemini prompt inlines, so the bot follows it); `getInvestments`' pulse derives buys from share-priced accounts, not categories, so it needs no discipline. Runway = the `isInvestedNetWorth` liquid side minus receivables minus credit.
- **D1 has no interactive transaction** — `batch()` only, no `BEGIN` across an await. Bulk ops are one batch of statements.
- **`not_found_handling` must stay unset** in `wrangler.toml`: `single-page-application` would answer `/api` with `index.html`. Screen routing is on `?screen=` query params.
- **A text variation selector won't stop Telegram emoji-fying a glyph.** It renders every `Emoji=Yes` codepoint with its own emoji font and ignores `U+FE0E`, so `↩︎` shipped as ↩️. Where a text look is wanted, pick a glyph outside the emoji set (`↻ ✎ ⌕ ◈ ✦ › →`). Error marks `❌`/`⛔` are **deliberately** emoji — leave them. Guarded by `test.js`.
- **Debugging the bot:** `npm run tail` while you send a message. Setting the webhook again clears `last_error_*` and `pending_update_count`, so read `getWebhookInfo` *after* a fresh test message and *without* re-setting it first.
- **A UI-only change still needs `wrangler deploy`** — `worker/public/` ships with the Worker. A GAS change needs `npm run push` and nothing else (no deployment exists).
- **Run `npm test` before pushing.** A new pure helper gets a test in `test.js`; anything touching SQL or a handler gets one in `test-api.js`; a new invariant whose failure is silent gets a contract guard.

Pure code/refactor/UI-behaviour changes need nothing. Same commit as the change. **Public repo: names of secrets, never values or URLs.**
