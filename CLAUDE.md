# CLAUDE.md
Guidance for Claude Code (and humans) working in this repo. **Keep this file and MEMORY.md token-efficient: dense, minimal blank lines, no filler; lines may exceed 80 chars. Apply the same when editing them.**

## Session protocol (read first)
- **Start:** if `HANDOFF.md` exists at repo root, read it before anything else — it's the resume point from the previous session. Then check MEMORY.md "TODO / open questions".

## Project overview
**FinanceTracker** is a **personal finance tracker**. Backend = **Google Apps Script (GAS)** over one Google Sheets workbook, published as a Web App exposing a small JSON API (record transactions, read accounts/categories) plus a scheduled daily-interest job.
- **Use:** personal finance tracking — log transactions, accounts, interest into a private Google Sheet.
- **Current client:** a private **Telegram bot running inside GAS** (`Telegram.gs`) — Telegram → **Cloudflare Worker** (`worker/`, answers the 200 that GAS can't) → `?action=telegram` → Gemini parse → service layer → reply. **n8n is retired** (2026-07-29) and its exports are deleted — `git show v1.3.2:'n8n/Finance Tracker.json'` if the old workflow is ever needed.
- **Frontend:** a **GAS Web App UI** (HTML via `doGet`/`HtmlService`) is **live** atop the API — responsive (desktop/tablet/mobile). See "Web App frontend" below.
- **Locale:** amounts in **PHP**; timezone `Asia/Manila`.
- **History:** the Phase 1–3 overhaul is **fully shipped (v1.3.4, 2026-08-02)** and its plan/migration runbooks are deleted — `git show v1.3.4:OVERHAUL_PLAN.md` / `git show v1.3.4:MIGRATION.md` for the design record; the decisions themselves live in MEMORY.md.

## How the backend works (service layer)
**Architecture:** one **service layer** owns every write + all rules; the UI (via `google.script.run`) and the Telegram bot (via `?action=`) both route through it. `Router.gs` is the sole `doGet`/`doPost` and dispatches to `api_*` handlers. **Schema invariant (post-migration):** derived columns (Month, Type, Segment, Currency, Amount (PHP), ToCurrency, the `.` index) are header-anchored **ARRAYFORMULA**s; the service writes **input columns only** (`SheetUtil.su_*InputRow_`) so a stray write never `#REF!`s a spill. `appendRow` is banned — it would clobber the derivation band.
**JSON API (`?action=`, POST only):** `createTransaction`, `createTransfer`, `updateTransaction`, `deleteTransaction`, `updateAccount`, `bulkUpdateTransactions`, `bulkDeleteTransactions`, `telegram`. Every tx has a stable server-assigned **`ID`**; `createTransaction` is idempotent if the caller passes an existing `ID`. Every write handler starts with `su_lock_()` (script lock, auto-released at execution end) so concurrent writes can't race the append-row calc or shifting row indices; bulk updates write one `getRangeList().setValue()` per patched field, not per cell. **All reads are UI-only via `google.script.run`** — `getBootstrap`, `listTransactions` (filters month/account/category/segment/search + `limit`/`offset`), `getAccounts`, `getDashboard`, `getInvestments`, `getBudgets` (optional `month=`), `getRecurring`, `getLedger`, `getCategories`, `getDataVersion` — as are the Ledger writes (`updateLedgerCell`/`appendLedgerRow`/`deleteLedgerRow`). Nothing external reads the API; to inspect sheet data, read the Sheet.
**Auth (`Auth.gs`):** writes pass `auth_requireWrite_` — allowed if the active user is `OWNER_EMAIL` (restricted deploy) **or** token enforcement is off **or** a valid `API_TOKEN` is supplied. The manifest **stays `ANYONE_ANONYMOUS` permanently**: Telegram's webhook can't do OAuth, so `access: MYSELF` would kill the bot. **End state reached 2026-07-29:** `ANYONE_ANONYMOUS` + `ENFORCE_TOKEN=true`, token carried in the Worker's `GAS_URL` secret (print it with `tg_gasEndpoint()`; rotating `API_TOKEN` means re-running `wrangler secret put GAS_URL`). Rollback = `ENFORCE_TOKEN=false`, no redeploy. The UI is unaffected — `google.script.run` bypasses the Router guard.
**FX (`Fx.gs`):** `ExchangeRate` is a **static stamped input** — per-tx override wins, else PHP→blank (formula treats blank as 1), else a cached live USD→PHP fetch, else `USD_PHP_FALLBACK`. History never reprices.
**Balances (`Accounts.gs`):** balances are **read from the sheet, not recomputed in code** — the Accounts tab already derives `Current Balance` (native) and `Current Balance (PHP)` by formula (Starting Balance + Σ transactions, live FX for non-PHP, Google Finance for Shares), and those SUMIFs update the instant the API appends a row. Same principle as the Transactions ARRAYFORMULAs: derivation lives in the Sheet. Each account exposes `balancePhp` (as shown — liabilities positive), `balanceNative` (Shares: this is the quantity), `netWorthPhp` (signed; liabilities negative), `availableCredit`, `isLiability`, `isShares`. The JS ledger sum survives only as `Tests.gs test_balanceReconciliation`, an independent **native-currency** integrity check (does the ledger agree with the sheet's balance formula?).
**Budgets (`Budgets.gs`):** the `Budgets` sheet holds the **plan only** (one row per segment: Segment, Period, Target Type, Target, Currency, Notes). Actuals/remaining/% are **computed in code** from the ledger (Σ |`Amount (PHP)`| of `Expense` **and `Transfer`** rows by Segment over the period window — current month, or the **calendar quarter** for `Period=Quarterly`), never stored. Transfers count because a segment like **Growth** is funded by moving cash → an investment account (an "Investment: Growth" transfer), so it must draw down the Growth budget; Income/other types never count — same spirit as derivation-in-the-sheet, but period/quarter logic is cleaner in code and matches Dashboard's `spendBySegment`. Hybrid targets: `Percent` rows resolve against `MONTHLY_INCOME_PHP` (×3 for Quarterly); `Amount` rows with `Currency=USD` convert at the **same live FX** as the rest of the app (no second pinned rate). `api_getBudgets` also returns an `essentialsRewards` roll-up. Recurring bills/installments live on a separate `Recurring` sheet (`api_getRecurring`), pure reference notes.
**`addDailyInterestTransactions(lookbackDays)` (`Interest.gs`):** math is `gross = closingBalance*rate/365` − 20% withholding (`interest_net_`), routed through `api_createTransaction` with a deterministic `ID` (`interest-<account>-<yyyy-MM-dd>`). The base is the day's **closing balance recomputed from the ledger** (`acct_computeDeltas_(asOfKey)`), not the live sheet balance at trigger time — so a backdated/late-logged transaction still prices its own day. It credits **closed days only** (never today) and re-prices the last `INTEREST_LOOKBACK_DAYS` (7) days each run, updating/deleting the existing row when the figure moved; the prior amount is subtracted from the base so repairs don't compound on their own output. Days run oldest→newest so a repair compounds forward. Manual backfill: `addDailyInterestTransactions(60)`. Daily time-based trigger, configured in the GAS UI.

## Web App frontend
**Serving:** a plain browser GET on the deployment URL (no `?action`) hits `Router.doGet` → `ui_serveApp_()` → `HtmlService` page. `Index.html` is a templated shell that `include()`s `Stylesheet.html` (CSS) + `App.html` (JS).
**Data path:** the SPA calls the service-layer `api_*` functions **directly through `google.script.run`** — no fetch, no URL-as-secret in client JS, no CORS. Calls run as the deploying owner (`executeAs USER_DEPLOYING`); reads bypass the Router's auth guard entirely (`ENFORCE_TOKEN` only gates `?action=` callers, i.e. the bot) — under the permanently anonymous deployment the UI's protection is the secret URL. Promise wrapper `gs(fn,arg)` rejects on `{status:'error'}`.
**Screens (vanilla JS, no framework — GAS has no bundler):** Dashboard (`getDashboard`: net worth/assets/liabilities, budget bars, balances-by-type, recent), Transactions (`listTransactions` filters+pagination; add/edit/delete + transfer via modals; FAB), Accounts (`getAccounts` grouped by Type; edit interest/limit/notes via `updateAccount` — editable cols only), Budgets (`getBudgets`+`getRecurring`: segment bars, `essentialsRewards`, recurring list), Investments (`getInvestments`: positions/weights, **read-only**), Tax (`getLedger` + editable via `Ledger.gs` — formula-derived columns rendered read-only; a **"Salary not in the ledger"** card lists `api_getLedger`'s `unlinked` — `Income: Salary` tx no row references — and "+ Add" appends a row writing *only* `Transaction ID`, the rest derives). **Deep links** (`google.script.url.getLocation`, the only params that reach the sandboxed iframe): `?screen=<name>` selects a screen; `?tx=<ID>` opens that transaction's edit modal (`api_listTransactions({id})`) — the target of the Telegram receipt's "Edit details" button. **Responsive:** mobile-first; bottom-nav on phone, left sidebar ≥860px. A month picker (`yyyy-MMM`) drives period-aware screens. After any write the SPA re-hydrates `getBootstrap` (balances/budgets shift).
**Perf (1.2.x):** screen payloads are cached client-side (`S.cache`) and revalidated through `cachedCall` + `api_getDataVersion` (see `Cache.gs` row); Transactions add/delete are **optimistic** (row painted/removed immediately, reconciled after the server responds); the add-form prefills the last-used account and autofocuses Amount.
**Deploy:** redeploy the **same `deploymentId`** so the URL (and the bot's webhook target) stays stable; the UI appears at the existing URL.

## Google Sheet structure (source of truth)
Code depends on these sheets/headers; keep them in sync.
- **`Transactions`** — header row drives `doPost`. Known columns: `Date`, `Category`, `Account`, `Amount`, `Period`. **`Period`** (input, usually blank) is the **reporting-month override**: `Month` = `IF(LEN(Period), Period, TEXT(Date,"yyyy-mmm"))`, so a salary paid Jul 31 with `Period=2026-Aug` reports under August while `Date` keeps the real cash movement (balances, reconciliation and daily interest all key off `Date`, so they stay honest). Everything month-keyed reads the derived `Month` — cash flow, budget actuals, `spendBySegment`, the Transactions filter — so nothing in the service layer special-cases it. Must be canonical `yyyy-MMM`; `tx_parsePeriod_` normalizes and rejects anything else (a bad key silently matches no month anywhere). **The column must stay formatted plain text (`@`)** — otherwise Sheets coerces `2026-Aug` into a date on write and `Month` spills the serial (`46235`), since `LEN()` still sees 5 chars; `setupTxPeriod` formats the column and the write paths re-stamp `@` per cell.
- **`Accounts`** — `Name`, `Currency`, `Subtype`, `Type` (**derived** = VLOOKUP of Subtype in `AccountType`; not hand-entered), `Starting Balance` (native), `Current Balance`/`Current Balance (PHP)` (formula = Starting + Σ tx, FX/Google-Finance), `Available Credit`, `Interest Frequency`, `Interest Rate`, `Credit Limit`, `Notes`, `Color` (optional hex for UI color-coding; added by `setupAccountColor`). Liabilities store balance **positive** (amount owed). `Name` is the immutable FK used by Transactions — never rename.
- **`AccountType`** — reference: `Subtype → Type` (Credit→Liability, else Asset). Drives the derived Accounts `Type`. Created by `Migration.setupAccountType`.
- **`Categories`** — `Category`, `Type`, `Segment`, `Description`. `Category` is the immutable FK used by Transactions.
- **`Budgets`** — plan only, one row per segment: `Segment`, `Period` (Monthly/Quarterly), `Target Type` (Percent/Amount), `Target`, `Currency` (USD→live FX; blank/PHP passes through), `Notes`. **No** stored actuals/derived columns — those are computed in `Budgets.gs`. Rebuilt by `Migration.setupBudgets`.
- **`Recurring`** — recurring bills / installment notes (split out of the old Budgets sheet): `Description`, `Currency`, `Amount`, `Transaction Fee`, `Months Left`, `Group`. Reference only; not used in any calc.
- **`Ledger`** — BIR 8%-regime tracker; still owner-extensible (an extra hand-added column is passed through untouched by the header-generic `Ledger.gs` writers), but the columns `setupLedgerSchema` manages are **named literally** in `MIG_LEDGER_*` — rename one in the sheet without renaming the constant and the migration adds a duplicate. **Inputs:** `Transaction ID` (FK → Transactions `ID`), `BSP Reference Rate`, `Filed?`. **Derived (per-row formulas, not ARRAYFORMULA — rows are appended/deleted individually and `api_deleteLedgerRow` really does `deleteRow`, which would break a spill anchor):** `Date Received`, `Wise Amount` (both `INDEX/MATCH` on the ID → tx `Date`/`Amount`), `Total Income` = `Wise Amount × BSP Reference Rate` (blank rate ⇒ 1, i.e. a PHP payslip), `8% Tax` = 8% of that. **`BSP Reference Rate` is deliberately not the app's `ExchangeRate`** — BIR wants the central bank's reference rate on the date of receipt, which the app has no feed for, so it stays hand-typed per payslip. A deleted transaction shows `⚠ transaction deleted` in `Date Received` rather than silently blanking.

## clasp workflow (push/deploy to Apps Script)
Full procedure (setup, push/pull, deploy invocations) is the **`clasp-deploy` skill**. Two rules that must not wait for it:
- **Never create a new deployment.** Redeploy the **same** `deploymentId` — a new deployment mints a new URL and silently breaks the bot's webhook target.
- **Web App access:** manifest stays `executeAs: USER_DEPLOYING` + `access: ANYONE_ANONYMOUS` — required, the Telegram webhook can't authenticate. The deployment URL is effectively the credential — treat as secret (kept out of git; see MEMORY.md). `ENFORCE_TOKEN=true` + the token in the Worker's `GAS_URL` secret is the write guard (live).

## Git workflow (gitflow + releases)
Gitflow (AVH, configured in `.git/config`; plain `git branch/merge` works too — the config just makes `git flow` commands match):
- **`main`** = released/live code only. **`develop`** = integration branch; day-to-day commits and merges land here.
- **Features:** `feature/<name>` off `develop`, merge back to `develop` (no tag, no release).
- **Release to main:** merge `develop` → `main`, then run **`npm run release`** — the ONLY way code reaches main/live. It: verifies on-main+clean, `clasp push -f`, redeploys the **same** `deploymentId` (from gitignored `.deploymentid` — URL stays stable for the bot), tags `v<package.json version>`, pushes main+tags, creates a GitHub Release with generated notes. Bump the version **before** merging: `npm version patch|minor --no-git-tag-version` on `develop` (or the release branch), commit it.
- **Hotfix:** `hotfix/<name>` off `main` → merge to `main`, bump patch version, `npm run release`, then **back-merge `main` → `develop`**.
- **Tags/Releases invariant:** every tag is `vX.Y.Z`, on `main`, created only by `release.js`, and has a matching GitHub Release; GAS deployment description = the tag. Never hand-create tags or Releases.
- Push `develop` freely; never push directly to `main` (only via release/hotfix merges followed by `npm run release`).

## Conventions & gotchas
- **Never commit credentials:** `.clasprc.json` and the deployment URL stay out of git; `.clasp.json` (`scriptId` only) is safe.
- **clasp pushes only whitelisted files** (`.claspignore`): manifest + `*.gs`/`*.js`/`*.html`. Docs, `package.json`, `node_modules/` never reach GAS.
- **`clasp pull` before editing** if the GAS editor may have changed, to avoid clobbering remote edits.
- **Unique global function names** across all `.gs` (flat namespace).
- **Match sheet headers exactly** — the service maps columns by header text; a renamed header silently breaks mapping.
- **Never write a derived/formula column.** Service writes go through `su_setInputCells_`/`su_appendInputRow_` (input columns only). Never reintroduce `appendRow` on `Transactions` — it writes every column and `#REF!`s the ARRAYFORMULA spills.
- **`google.script.run` can't take a `Date` nested in an object** — passing `{Date:new Date(...)}` throws "Failed due to illegal property: date". The UI sends the date as an ISO `yyyy-MM-dd` **string**; `Transactions.gs tx_parseDate_` re-hydrates it to a real Date (local/script-tz, no UTC day-shift) before the input-row write so the Month ARRAYFORMULA still derives. (Distinct from the return-value rule in `SheetUtil.su_dateStr_`: a Date in the *response* nulls the whole payload.)
- **Every new write handler** must start with `su_lock_()` and end with `cache_bumpVersion_()` (plus `su_invalidateMemo_` if it reads the sheet it just wrote in the same execution) — otherwise the SPA's version-gated cache keeps serving stale data after the write.
- **Run `npm test` before pushing** — it needs no Google account, so Claude/CI can run it. A new pure helper gets a test function + an entry in `PURE_TESTS` (Tests.gs); sheet-bound checks stay editor-only in `test_all`.
- **A text variation selector won't stop Telegram emoji-fying a glyph.** It renders every `Emoji=Yes` codepoint with its own emoji font and ignores `U+FE0E` (VS15), so `↩︎` shipped as ↩️. Where a text look is wanted, pick a glyph outside the emoji set (`↻ ✎ ⌕ ◈ ✦ › →`), not a selector. Error marks `❌`/`⛔` are **deliberately** emoji — leave them. Undo glyph guarded by `test_telegramUndoGlyph`.
- **Debugging the bot: `tg_setWebhook` clears `last_error_*` and `pending_update_count`.** Read `tg_webhookInfo` *after* a fresh test message and *without* re-running `tg_setWebhook`, or you're reading a wiped counter and will conclude nothing is wrong.
- After changing bot/API behavior, **redeploy** — saved editor code doesn't affect the live Web App, so `npm run push` alone does not update what Telegram hits.
- Keep **MEMORY.md** current: decisions, trigger setup, secret locations.
- **No Claude metadata in commits:** never add `Co-Authored-By: Claude ...` or `Claude-Session: ...` trailers to commit messages.
