# The SPA frontend

Files this skill covers.

| File | Purpose |
| --- | --- |
| `worker/public/index.html`·`app.css`·`app.js`·`sw.js` | The responsive SPA, served as static assets. Unchanged by the platform swap apart from the Admin screen — see "Web App frontend". |
| `icons.js` → `worker/public/icon-180.png`/`icon-512.png` | App icon: **accent-blue tile (`#5b8cff`), white `₱`**. **The art is the `ICON` SVG string inside `icons.js` — there is no binary master.** The two PNGs are generated — never hand-edit them: `npm run icons` renders the SVG with whatever Chrome/Edge is installed (`--headless --screenshot`). 180 = `apple-touch-icon` + favicon, 512 = manifest; both `purpose:"any maskable"`, glyph inside Android's 80% safe circle. **Deliberately square with no rounded corners** — iOS rounds the apple-touch-icon and Android masks the maskable one, so baked-in corners double-round. The `₱` is a font glyph (`Segoe UI`/`Helvetica Neue`/`Arial`), not a path; widen that stack if a regen on another OS tofus. **Centring is horizontal-by-default, vertical-by-hand:** `text-anchor="middle"` already centres at `x=48` (don't "correct" it), but `dominant-baseline="central"` lands a caps-only glyph ~6.55% too low — hence the `48 - 0.0655*GLYPH` lift, verified at sizes 48/58/66/72. |

## Web App frontend
**Serving:** the Worker serves `worker/public/` as static assets, same origin as `/api`. No bundler, no build step.
**Data path:** `gs(fn, arg)` → `/api`. Reads GET, writes POST, chosen from the handler-name prefix. `gs()` rejects on `{status:'error'}`, and on a **401** asks for the passphrase once (`unlock()` → `POST /login`) and retries. `unlock()` renders a **real `<form>` in the app's own modal — never `window.prompt`**: prompt shows the passphrase in clear text, no password manager can fill it, and its iOS field autocapitalises. `type=password` + `autocomplete="current-password"` (plus a readonly username field so the saved entry has a name) is what gets iOS AutoFill. Concurrent 401s share one dialog (`_unlocking`); a wrong passphrase re-asks in place; cancelling must settle the promise (`closeModal.onClose`) or every later 401 awaits a dead one.
**Screens:** Dashboard (incl. the **net-worth bridge** card — ΔNW split into savings and "market, FX & timing", absent for a month whose predecessor has no snapshot) · Transactions (filters/pagination + the Edit toggle: account rail, checkboxes, bulk bar, inline single-field edit — one `txRow(t,opts)` renders both modes; `?screen=review` is dead) · Budgets · Accounts (incl. the Holdings, Quarterly-pulse and Emergency-runway cards, all filled by one `cachedCall('investments')`; Holdings carries average cost and peso gain, and the pulse draws its bar from BUYS only — a sell is a red detail line and a dashed empty track, because the bar measures money going in) · Swap · Tax · **Admin**. Deep links: `?screen=<name>` wins over the stored last screen; `?tx=<ID>` opens that transaction's edit modal (the Telegram receipt's target) via `openTxById`. Mobile-first: bottom-nav + a More sheet on phone, left sidebar ≥860px.
**Admin screen (new in v2.0.0):** a generic CRUD grid over the server-side whitelist. **The Sheet used to be the admin UI** — adding a category, retiring an account, fixing a budget target were all "open the tab and edit the cell" — so this replaces exactly that. It renders whatever `listTable` tells it: the server owns which tables exist, which columns are editable (`edit`), which are settable on insert (`add` — a natural PK appears there and not in `edit`, because renaming one under a live FK is data loss, not a cell edit) and which are micros (`money`, converted both ways at the boundary). **`transactions` is read + delete only** — it has real handlers with validation and FX stamping, and the grid must not be a way around them. **`nw_snapshots` is fully read-only** (`edit:[]` + `nodelete:true`): cron-owned history the grid must not hole; `listTable` reports `deletable:false` and the client hides the ✕. No SQL console, deliberately: anything this can't express is `wrangler d1 execute`.
**Tax screen:** `getLedger` returns `rows` keyed by the **sheet's old header names** (`__row` is now the ledger row id — an opaque handle, so the client is unchanged), `cols` in `LEDGER_COL_ORDER`, and `derived` (rendered read-only). `Filed?` is a native `<select>` of BIR quarters (`quarterSelect`), deliberately not the fuzzy combobox. The subtitle links out to the BSP daily rate page — **`BSP Reference Rate` is deliberately not the app's FX**: BIR wants the central bank's reference rate on the date of receipt, which the app has no feed for, so it stays hand-typed per payslip. The "Salary not in the ledger" card lists `unlinked` and "+ Add" appends a row writing *only* `Transaction ID`; everything else derives.
**Non-obvious UI constraints:** chart series tokens `--chart-income #27ad75` / `--chart-spend #d95757` (red, = `--chart-neg`; was blue `#5b8cff` until spending went red) are contrast-validated against the card surface — revalidate if changed. **Income-green vs spending-red is a red/green CVD-confusable pair**, mitigated by position (income bar left, spend right), the legend, and the tooltip — colour is never the only channel. The net-worth line is `--accent` (blue), distinct from both. Form/filter pickers are a custom **fuzzy combobox** (`comboEl`/`fuzzyScore`), deliberately not `<select>`. The quick-add **FAB adds transfers too** — `typeToggleEl` swaps `openTxModal`⇄`openTransferModal` in place, carrying Date/Account(→From)/Amount/Description but **not** Category (disjoint sets).
**Fonts are ours, not Google's:** Inter ships as two woff2 subsets in `worker/public/fonts/`, declared by `@font-face` at the top of `app.css` and listed in `sw.js`'s `SHELL` — so the typeface survives offline. Google Fonts cost **146 KB** on a cold install (72% of it), across two extra origins, and its stylesheet had a 1-day `max-age`, so it came back daily. The **`unicode-range` on each `@font-face` is copied verbatim from Google's CSS and must stay**: it is what stops a page with no peso sign downloading the 85 KB `latin-ext` file. **₱ (U+20B1) lives in `latin-ext`, not `latin`** — one glyph pulls the bigger file, which is why subsetting the pair is the next rung if the budget ever matters more than having no toolchain. The files are variable (weight axis 400–800), so `font-weight:650`/`750` in `app.css` are real weights, not rounded ones. OFL 1.1, `fonts/OFL.txt`.
**Perf:** payloads are cached client-side (`S.cache` = `key → {data, etag, at}`, persisted to localStorage) and revalidated through `cachedCall`. **The revalidation is an ETag, not a version (v2.9.0):** the loader is `function(etag)`, `gs()` sends it as `If-None-Match`, and a 304 comes back as `{__304:true}` — keep the paint, restamp `at`. A 200 carries `__etag`, which `cachedCall` lifts off before storing. The old `meta.data_version` counter moved on EVERY write, so a Telegram ingest the owner never saw re-downloaded every cached screen; a tag over the payload's own bytes is the only thing that can see the month-, year- and page-scoped keys. **`S.bootEtag` does the same for `getBootstrap`** — the biggest single payload, now a 304 on a relaunch that changed nothing. Dashboard/Budgets keys are month-scoped, so `monthPickerEl` must **not** wipe `S.cache` on change. Transactions add/delete are optimistic. **`LS_SCHEMA` is a cached-payload shape stamp — bump it whenever a payload's shape changes** (9 = ETag entries + `getBudgets` carrying `recurring`). **There is no push:** a screen left open never updates itself; the app revalidates on navigation. **`dropCache()` after a write keeps the TAGS** and only clears the freshness stamps — the screens the write did not move then answer 304 instead of refetching; `refresh()` is the one that goes properly cold. **Data Saver (`navigator.connection.saveData`) buys two things:** `REVAL_TTL` becomes 60s instead of 3s, and `sw.js` serves a cached shell file WITHOUT the background revalidation — on a cell connection the radio wake-up costs more than the 304 does. Refresh clears the cache and the whole `caches` store, so it stays the escape hatch for both. **The Dashboard is the one screen that cannot 304 after a write** — every month of it carries the live net-worth hero, so the bytes really do change. **One page, never a whole table:** the Admin grid pages at `ADMIN_PAGE` (50) with `listTable`'s `offset`; its ↓ CSV button calls `adminFetchAll` so the FILE is still the whole table (the old `limit:500` grid silently truncated it). The Tax screen asks `getLedger` for one year and picks it with `ledgerYearSelect`.
**App-shell scrolling (v1.6.5), don't undo it:** `html,body{overflow:hidden}` and `#app` is exactly one viewport tall, so **`.main` is the only scroller** — the document must never scroll, or iOS rubber-band overscroll drags the topbar/nav off the screen edges. Height comes from **`--app-h`, set in JS in `index.html` before first paint**, because iOS standalone + `black-translucent` + `viewport-fit=cover` reports `innerHeight` as **screen minus the top inset** (797 vs 844 on a 390×844 phone) while painting from y=0 — only `screen.height` sees it, and the shim keys on `screen.height === innerHeight + insetTop` so every other platform falls through. The nav's ~34px bottom padding **is the home-indicator clearance, not a bug**. Changing `apple-mobile-web-app-status-bar-style` is not a fix path: **iOS reads those metas at Add-to-Home-Screen time.**
**Offline (v1.6.1):** three layers. **Shell** — `sw.js` caches `/`, `/app.css`, `/app.js`, `/manifest.json` cache-first (`ignoreSearch`, so a deep link matches the cached `/`); it deliberately **never caches `/api`**. **Reads** — the persisted `S.cache` (a failed revalidation keeps the stale paint). **Writes** — a `localStorage` queue (`ft.queue`) flushed on `online`, at launch, and by Refresh. **Only `createTransaction`/`createTransfer` are queued** (`QUEUEABLE`) because only they are idempotent on a client-supplied ID — `gs()` stamps a `ui-<ts>-<rand>` ID *before* the first attempt for exactly that reason. Everything else refuses with an offline message. Pending rows are derived from the queue (`rebuildPending`). A flush **discards a queued write only when the server explicitly rejects the payload** (`_server`); offline, a lapsed cookie, a cancelled prompt or a 5xx all keep it and stop the run — dropping money because the cookie lapsed would be the worst bug in here. `flushQueue._busy` is what stops `gs()` re-queueing during a flush.
