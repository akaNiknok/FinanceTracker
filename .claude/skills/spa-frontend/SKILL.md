# The SPA frontend

**The look is `DESIGN.md` (repo root) — read it before changing anything visible.** This skill is the mechanics; that file is the tokens, layout, components and motion. The v3 redesign is in progress per `V3_PLAN.md` while that file exists: where a paragraph below still describes v2 content (dashboard cards, the Transactions filters), the plan's phase for it wins. The shell, tokens, theme and fonts are v3 already (Phase 1).

| `icons.js` → `worker/public/icon-180.png`/`icon-512.png` | App icon: **accent-blue gradient tile (`#4A86FF`→`#1D4ED8`), faint rising line, white `₱`**. **The art is the `ICON` SVG string inside `icons.js` — there is no binary master.** The two PNGs are generated — never hand-edit them: `npm run icons` renders the SVG with whatever Chrome/Edge is installed (`--headless --screenshot`). 180 = `apple-touch-icon` + favicon, 512 = manifest; both `purpose:"any maskable"`, glyph inside Android's 80% safe circle. **Deliberately square with no rounded corners** — iOS rounds the apple-touch-icon and Android masks the maskable one, so baked-in corners double-round. The `₱` is a font glyph (`Segoe UI`/`Helvetica Neue`/`Arial`), not a path; widen that stack if a regen on another OS tofus. **Centring is horizontal-by-default, vertical-by-hand:** `text-anchor="middle"` already centres at `x=48` (don't "correct" it), but `dominant-baseline="central"` lands a caps-only glyph ~6.55% too low — hence the `48 - 0.0655*GLYPH` lift, verified at sizes 48/58/66/72. |

## Web App frontend
**Serving:** the Worker serves `worker/public/` as static assets, same origin as `/api`. No bundler, no build step.
**Data path:** `gs(fn, arg)` → `/api`. Reads GET, writes POST, chosen from the handler-name prefix. `gs()` rejects on `{status:'error'}`, and on a **401** asks for the passphrase once (`unlock()` → `POST /login`) and retries. `unlock()` renders a **real `<form>` in the app's own modal — never `window.prompt`**: prompt shows the passphrase in clear text, no password manager can fill it, and its iOS field autocapitalises. `type=password` + `autocomplete="current-password"` (plus a readonly username field so the saved entry has a name) is what gets iOS AutoFill. Concurrent 401s share one dialog (`_unlocking`); a wrong passphrase re-asks in place; cancelling must settle the promise (`closeModal.onClose`) or every later 401 awaits a dead one.
**Screens:** Summary (key `dashboard`, v3 Phase 2: the `.sum` tile grid — net worth with sparkline and bridge chip, Left to spend (the Essentials+Rewards roll-up plus every budget as a segment row, off `getDashboard`'s budgets payload), Financially free in, Emergency runway (read from `cachedCall('investments')`, the Accounts payload, whose `runway.parts` are the tooltip rows), the history tile (`historyCharts`: net-worth stack and cash-flow bars on ONE band per month, one inspect line and tooltip through both, 6M/1Y/2Y = `S.cfMonths`), spending by category, recent. Spans live in `app.css`; the charts mount at rAF at the host's width. The Budgets screen was merged into it in v2.14.0 and `getBudgets` stays a route for an old cached `app.js`; the Recurring card went to Accounts and reads `S.boot.recurring`) · Transactions (filters/pagination + the Edit toggle: account rail, checkboxes, bulk bar, inline single-field edit — one `txRow(t,opts)` renders both modes; `?screen=review` is dead) · Accounts (incl. the Holdings, Quarterly-pulse and Emergency-runway cards, all filled by one `cachedCall('investments')`; Holdings carries average cost and peso gain, and the pulse counts GROWTH tickers only — EF parking (IB01) is a holding but not investing — and draws its bar from BUYS only, a sell being a red detail line and a dashed empty track, because the bar measures money going in) · Swap · Tax · **Admin**. Deep links: `?screen=<name>` wins over the stored last screen; `?tx=<ID>` opens that transaction's edit modal (the Telegram receipt's target) via `openTxById`. Labels are Summary and Activity; the keys stay `dashboard` and `transactions`.
**Admin screen (new in v2.0.0):** a generic CRUD grid over the server-side whitelist. **The Sheet used to be the admin UI** — adding a category, retiring an account, fixing a budget target were all "open the tab and edit the cell" — so this replaces exactly that. It renders whatever `listTable` tells it: the server owns which tables exist, which columns are editable (`edit`), which are settable on insert (`add` — a natural PK appears there and not in `edit`, because renaming one under a live FK is data loss, not a cell edit) and which are micros (`money`, converted both ways at the boundary). **`transactions` is read + delete only** — it has real handlers with validation and FX stamping, and the grid must not be a way around them. **`nw_snapshots` is fully read-only** (`edit:[]` + `nodelete:true`): cron-owned history the grid must not hole; `listTable` reports `deletable:false` and the client hides the ✕. No SQL console, deliberately: anything this can't express is `wrangler d1 execute`.
**Tax screen:** `getLedger` returns `rows` keyed by the **sheet's old header names** (`__row` is now the ledger row id — an opaque handle, so the client is unchanged), `cols` in `LEDGER_COL_ORDER`, and `derived` (rendered read-only). `Filed?` is a native `<select>` of BIR quarters (`quarterSelect`), deliberately not the fuzzy combobox. The subtitle links out to the BSP daily rate page — **`BSP Reference Rate` is deliberately not the app's FX**: BIR wants the central bank's reference rate on the date of receipt, which the app has no feed for, so it stays hand-typed per payslip. The "Salary not in the ledger" card lists `unlinked` and "+ Add" appends a row writing *only* `Transaction ID`; everything else derives.
**Non-obvious UI constraints:** chart series tokens are `--chart-in` / `--chart-out` (v3 renamed `--chart-income`/`--chart-spend`; values per theme in DESIGN.md) — revalidate 3:1 against `--card` in both themes if changed. **Income-green vs spending-red is a red/green CVD-confusable pair**, mitigated by position (income bar left, spend right), the legend, and the tooltip — colour is never the only channel. The net-worth line is `--accent` (blue), distinct from both. Form/filter pickers are a custom **fuzzy combobox** (`comboEl`/`fuzzyScore`), deliberately not `<select>`. The add field's **full form adds transfers too** — `typeToggleEl` swaps `openTxModal`⇄`openTransferModal` in place, carrying Date/Account(→From)/Amount/Description but **not** Category (disjoint sets). **Desktop ≥1200px is two columns (`.cols` on the screen root, `columns:2` in `app.css`), not a grid** — a grid row is as tall as its tallest card, so one long account list left a half-screen void; multicol balances instead. A card that needs the full width carries `wide` (`column-span:all`): both dashboard charts, the KPI row, and `.hero-row` — the wrapper that pairs the FI and net-worth heroes into one equal-height row (`display:contents` below 1200px, so the phone stack is untouched; without it the two land in different columns at their own heights and leave a ragged gap under the shorter one). **`wide` is set in JS, never by `:has(svg)`** — a chart is appended at rAF, so the column count would change after the chart measured its host. `#invCards` is `display:contents` there, or its four cards are one unbreakable block.
**No web fonts (v3):** the system stack (`--font`, DESIGN.md "Typography"). Inter used to ship self-hosted in `worker/public/fonts/` (it had replaced a 146 KB Google Fonts download); v3 deleted it with its `@font-face`, preload and `sw.js` `SHELL` entries, so text costs nothing and works offline. Do not add a font file back.
**Shell (v3):** one `<nav id="nav">` in `index.html` is three layouts by width in `app.css`: a tab bar under 768px (Summary, Activity, Accounts, More — the More sheet holds Swap/Tax/Admin plus the sync state and theme button), a 76px icon rail at 768–1199px, a 240px sidebar from 1200px. The add field (`.addbar`, `#addInput`) is docked above the tab bar on a phone and a header row from 768px; `wireShell()` wires it, the theme and the sync state. **Theme:** `ft.theme` = `light`/`dark`/absent (Auto); the head script in `index.html` sets `data-theme` and the `theme-color` meta before first paint, `applyTheme()` does the same at run time — keep the two in step. **Sync state** (`syncText`/`syncUI`): offline is what `gs()` last saw (`netSeen`), never `navigator.onLine`; the count is `queue().length`. **Icons:** the `<symbol>` sprite in `index.html`; `icon('name')` returns the markup. **`tip(spec)`** returns the ⓘ button for a derived figure (spec = `{title,text,rows:[[label,value,bold]],note}`, or a function returning it so the rows read live values); `tipHTML` is the pure part and is tested.
**Perf:** payloads are cached client-side (`S.cache` = `key → {data, etag, at}`, persisted to localStorage) and revalidated through `cachedCall`. **The revalidation is an ETag, not a version (v2.9.0):** the loader is `function(etag)`, `gs()` sends it as `If-None-Match`, and a 304 comes back as `{__304:true}` — keep the paint, restamp `at`. A 200 carries `__etag`, which `cachedCall` lifts off before storing. The old `meta.data_version` counter moved on EVERY write, so a Telegram ingest the owner never saw re-downloaded every cached screen; a tag over the payload's own bytes is the only thing that can see the month-, year- and page-scoped keys. **`S.bootEtag` does the same for `getBootstrap`** — the biggest single payload, now a 304 on a relaunch that changed nothing. The dashboard key is month-scoped, so `monthPickerEl` must **not** wipe `S.cache` on change. Transactions add/delete are optimistic. **`LS_SCHEMA` is a cached-payload shape stamp — bump it whenever a payload's shape changes** (10 = the Dashboard carrying the budgets payload). **There is no push:** a screen left open never updates itself; the app revalidates on navigation. **`dropCache()` after a write keeps the TAGS** and only clears the freshness stamps — the screens the write did not move then answer 304 instead of refetching; `refresh()` is the one that goes properly cold. **Data Saver (`navigator.connection.saveData`) buys two things:** `REVAL_TTL` becomes 60s instead of 3s, and `sw.js` serves a cached shell file WITHOUT the background revalidation — on a cell connection the radio wake-up costs more than the 304 does. Refresh clears the cache and the whole `caches` store, so it stays the escape hatch for both. **The Dashboard is the one screen that cannot 304 after a write** — every month of it carries the live net-worth hero, so the bytes really do change. **One page, never a whole table:** the Admin grid pages at `ADMIN_PAGE` (50) with `listTable`'s `offset`; its ↓ CSV button calls `adminFetchAll` so the FILE is still the whole table (the old `limit:500` grid silently truncated it). The Tax screen asks `getLedger` for one year and picks it with `ledgerYearSelect`.
**App-shell scrolling (v1.6.5), don't undo it:** `html,body{overflow:hidden}` and `#app` is exactly one viewport tall, so **`.main` is the only scroller** — the document must never scroll, or iOS rubber-band overscroll drags the topbar/nav off the screen edges. Height comes from **`--app-h`, set in JS in `index.html` before first paint**, because iOS standalone + `black-translucent` + `viewport-fit=cover` reports `innerHeight` as **screen minus the top inset** (797 vs 844 on a 390×844 phone) while painting from y=0 — only `screen.height` sees it, and the shim keys on `screen.height === innerHeight + insetTop` so every other platform falls through. The nav's ~34px bottom padding **is the home-indicator clearance, not a bug**. Changing `apple-mobile-web-app-status-bar-style` is not a fix path: **iOS reads those metas at Add-to-Home-Screen time.**
**Offline (v1.6.1):** three layers. **Shell** — `sw.js` caches `/`, `/app.css`, `/app.js`, `/manifest.json` network-first with a 3 s timeout, cache as the fallback (v3; cache-first put every deploy on the second launch) (`ignoreSearch`, so a deep link matches the cached `/`); it deliberately **never caches `/api`**. **Reads** — the persisted `S.cache` (a failed revalidation keeps the stale paint). **Writes** — a `localStorage` queue (`ft.queue`) flushed on `online`, at launch, and by Refresh. **Only `createTransaction`/`createTransfer` are queued** (`QUEUEABLE`) because only they are idempotent on a client-supplied ID — `gs()` stamps a `ui-<ts>-<rand>` ID *before* the first attempt for exactly that reason. Everything else refuses with an offline message. Pending rows are derived from the queue (`rebuildPending`). A flush **discards a queued write only when the server explicitly rejects the payload** (`_server`); offline, a lapsed cookie, a cancelled prompt or a 5xx all keep it and stop the run — dropping money because the cookie lapsed would be the worst bug in here. `flushQueue._busy` is what stops `gs()` re-queueing during a flush.
